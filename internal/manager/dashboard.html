How work moves

1. Phone managerYou request work and state the minimum CPU/memory needed.
→
2. Placement + secure transferThe manager selects a READY node, then sends the workload over pinned TLS/WebSocket.
→
3. Desktop agentThe agent starts the process, captures output/exit status, and reports lifecycle events back.

Only control messages and task output travel through the harness. The actual CPU and memory are consumed on the selected desktop.

Revoked devices

Refused on every reconnect, even with the shared pairing token. Revocation denies one identity: a device that knows the shared pairing token can enroll a new one, so also restart the manager with a new -pairing-token to cut it off completely.

Audit log

Admissions (and how each device got in), revocations, invitations, updates, sign-ins and workloads, newest first. It records what happened; it is not protection against someone who already holds the operator token.

Run a task

Typed tasks are built into every agent and run the same on every device, inside their own folder with only the files you give them.

Run a visible test

For CPU pulse, open the device's task manager / activity monitor before dispatching.

Advanced: raw command

The program runs inside its own folder holding the inputs, so run scripts through their interpreter. Outputs come back here to download.

Policy: what the fleet may run

Raw commands and host file reads run anything on a device: they stay off unless you turn them on, ideally only for devices you label (e.g. raw=ok in Rename/labels).

Add a device

Another Windows desktop: keep it on the same Wi-Fi, enter this phone's current Wi-Fi address plus :7420, choose Windows, create a fresh QR/link, then open the full HTTPS link on that desktop. Accept the local certificate warning and run the displayed PowerShell command. Keep that agent process running.

The phone IP can change when Wi-Fi changes. Generate a new link with the new address, or use LAN discovery/a reserved DHCP address. Remote mode needs the separate public relay.

Not auto-detected on purpose — a multi-homed machine has no single "right" address to guess.

QR + link uses the relay's public HTTPS enrollment gateway and downloads automatically. The plain “Generate script” fallback still expects the matching binary to be placed on the device first.
