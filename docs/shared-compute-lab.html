1 · How a large task gets split

The test job: draw one 7000 × 5500 picture of a fractal (38 million pixels, up to 20,000 steps of maths per pixel). One device needs minutes. The harness cuts it into 48 horizontal strips — each strip is an ordinary task.

CutThe job lists 48 independent strips, each saying "draw rows A to B".
PlaceFor every strip the manager picks the least-busy device that can run it and has free memory.
RunEach device draws its strip using all its cores, then asks for nothing more until the manager hands it another.
JoinWhen all 48 are done, one more task stacks the strips into the final picture.

Nobody told the Air to take half. A faster device finishes strips sooner, so the manager has a free slot to give it again sooner. Speed decides the split.

2 · What it buys you

Laptop alone
Laptop + 2 Macs

The drawing got 3.3× faster (132 s → 40 s), but the whole job only 2.6×, because the last step — joining the 48 strips into one picture — is a single task of about 20 seconds that no device can share. That fixed tail is a third of the spread-out run. Small jobs gain even less: a lighter version of this picture took 13 seconds alone and 9 spread out. Big jobs with a short tail gain the most.

Rule of thumb. A task spreads well if it breaks into many independent pieces that each take at least several seconds: renders, batches of photos, transcribing many recordings, word counts over big files (map-reduce), parameter sweeps. It does not spread if every step needs the previous step's answer.

3 · Local inference lab

Each device runs a model on its own, with no network involved. The same prompt, 160 tokens, greedy decoding, run through the harness's llm.generate task three times.

Devices with different models are not a race: the Air's 4B model is four times larger than the laptop's 1B but answers just as fast, because the Air's Apple chip is far quicker per parameter. This is what the planner uses to choose a device for an AI task.

4 · Shared inference lab

One model split across two devices with llama.cpp: the laptop holds part of the model and sends the numbers over Wi-Fi to the Mac, which holds the rest. The harness starts both halves, wires them together and exposes the result as one chat address.

Honest reading. For a model that fits on one device, splitting it is about 30× slower: every generated word needs a round trip across Wi-Fi. Shared inference earns its place only when the model is too big for any single device (for example a 30B model across three 16 GB machines) — then slow beats impossible. I could not show that case today: it needs a multi-gigabyte model on the main device, and the Intel Mac dropped off the network twice during the split runs, which also ended the second request (the model server stopped). Earlier sessions ran a tiny model split across both devices successfully.

5 · Training across devices

Training splits differently: not by pieces of one answer, but by data. Each device learns from its own share of the text, then the manager averages what they learned and the next round starts from the average. Only a 2 MB adapter travels, never the model.

Round by round, the laptop (5 s per step, busy) was given half the steps of the Intel Mac (2.8 s per step) so both finished together. Average loss fell 2.92 → 2.72 in three rounds on a small made-up text — a proof that the pipeline works, not a useful model yet.
